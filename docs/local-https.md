# Local HTTPS for the CodeRaft Dashboard

The CodeRaft installer ships with a local HTTPS reverse proxy (Caddy) so
the dashboard is reachable at `https://coderaft.local` instead of the plain
`http://localhost:3000`. This avoids browser HTTPS warnings and keeps the
dashboard on the same security model as a production deployment (secure
cookies, OAuth/OIDC redirects, mixed-content rules…).

> **TL;DR (since 2026-07)**: Caddy issues the certificate itself via its
> **internal CA** (`tls internal`). The installer waits for Caddy to
> generate `root.crt`, exports it with `docker compose cp`, and adds it to
> the OS trust store. No external tool is installed — **mkcert has been
> removed**. If anything fails the platform stays usable on
> `http://localhost:3000`, and the CA can always be downloaded later from
> the dashboard (Setup → TLS).

---

## Architecture

```
   Browser ── https://coderaft.local ──▶ caddy (:443)
                                            │  tls {$CADDY_TLS_MODE_ARGS:internal}
                                            ▼
                                        dashboard:3000 (nginx SPA + API proxies)
```

| Service     | Port (host)                       | Purpose                                    |
|-------------|-----------------------------------|--------------------------------------------|
| `caddy`     | `${CADDY_BIND_ADDR:-127.0.0.1}:443`, `:80` | TLS terminator, HTTP → HTTPS redirect |
| `dashboard` | `127.0.0.1:3000`                  | Plain HTTP fallback (backward compat)      |

By default everything is bound to **loopback only**. The Exposure step of
the Setup Wizard widens `CADDY_BIND_ADDR` to `0.0.0.0` for LAN /
port-forward / reverse-proxy modes. The Caddy admin API stays disabled
(`admin off`).

## TLS modes (env-templated Caddyfile)

The `Caddyfile` is static and reads its TLS configuration from env
placeholders, driven by `.env`:

| Mode | `CADDY_TLS_MODE_ARGS` | Use case |
|---|---|---|
| `internal` (default) | `internal` | LAN deployments, zero dependency |
| `wildcard` | `/certs/wildcard.crt /certs/wildcard.key` | customer wildcard cert (uploaded via the dashboard Setup Wizard) |
| `acme` | `<contact-email>` | Let's Encrypt for publicly exposed deployments |

Mode switching is done from the **dashboard Setup Wizard (TLS step)** —
dashboard-api updates `.env` and recreates the caddy service. Do not edit
the Caddyfile by hand. Related variables: `CODERAFT_HOSTNAME` (primary
hostname), `CODERAFT_TLS_SITES` (site list; apex only in ACME mode —
HTTP-01 cannot issue wildcards), `CADDY_BIND_ADDR`.

## The internal CA

- Generated by Caddy on **first start**, stored in the `caddy_data` Docker
  volume at `/data/caddy/pki/authorities/local/root.crt`.
- **Never delete the `caddy_data` volume between installs/updates** — the CA
  would be regenerated and every endpoint/agent that trusted the old one
  breaks.
- The installer trusts it automatically:
  - **Windows**: `Import-Certificate -CertStoreLocation Cert:\LocalMachine\Root`
    (single UAC prompt when not elevated)
  - **macOS**: `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain caddy-root.crt`
  - **Linux**: copy to `/usr/local/share/ca-certificates/` +
    `update-ca-certificates` (or `update-ca-trust` on RHEL-family)
- Fleet distribution (GPO / Intune / manual PowerShell): download the
  ready-made package from the dashboard — Setup → TLS → *Download GPO
  package* (`root.crt` + `install-ca.ps1` + `install-ca.gpo.xml` + README).
- Firefox keeps its own store: enable `security.enterprise_roots.enabled`.

## Hosts file

The installer adds (unless `CODERAFT_SKIP_HOSTS=1`):

```
127.0.0.1 coderaft.local entraguard.coderaft.local ravenscan.coderaft.local redfox.coderaft.local # coderaft-platform
```

## Opt-outs & troubleshooting

- `CODERAFT_SKIP_HTTPS=1` — skip the CA trust step (HTTPS is still served,
  but browsers warn until you trust the CA manually).
- `CODERAFT_SKIP_HOSTS=1` — skip the hosts-file entry.
- Browser still warns → the CA is not in the trust store; re-download it
  from Setup → TLS, or check
  `docker compose exec caddy ls /data/caddy/pki/authorities/local/`.
- Migrating from a pre-2026-07 install → the installer backs up the old
  mkcert-based `Caddyfile` to `Caddyfile.mkcert.bak` and regenerates the
  env-templated one. The old mkcert CA in your trust store is harmless and
  can be removed with `mkcert -uninstall` if mkcert is still installed.
- Full user guide (modes, exposure, Cloudflare Tunnel, port-forward):
  `coderaft-platform/docs/setup-tls-and-exposure.md`.
